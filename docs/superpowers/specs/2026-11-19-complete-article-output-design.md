# 完整文章输出设计

## 目标

让 Claude Sonnet 5.5 在生成约 2500 字文章时不再因为旧的 4096 token 上限而中途截断，同时避免完整文章产生额外请求和费用。

## 已确认原因

- EvoLink 的 Claude Messages API 要求请求必须包含 `max_tokens`，因此不能删除该字段。
- 网站从旧版本开始一直使用 `max_tokens: 4096`；这不是本次模型选择功能新增的限制。
- Sonnet 5.5 会使用内部思考，思考与正文共同占用输出额度，旧上限可能在正文完成前耗尽。
- 现有流式解析按网络数据块直接拆行，若一条 SSE 消息跨越两个数据块，可能丢失部分内容。

## 方案

1. 将生成和续写请求的 `max_tokens` 从 4096 提高到 12000。该值只表示允许的最高额度，文章目标长度仍由课程提示词中的“约 2500 字”控制。
2. 流式读取时保留未完整的 SSE 行，等下一数据块到达后再解析，避免网络分块造成正文片段丢失。
3. 读取接口返回的停止原因。若停止原因为 `max_tokens`，或正文末尾明显是未完成句子，则自动续写一次并无缝拼接。
4. 完整文章不触发续写。自动续写一次后仍不完整时，保留“⚠️ 未写完”和手动“续写”按钮，避免循环请求和不可控费用。

## 用户体验

- 用户仍然只需填写 API Key、选择模型并点击生成。
- 正常完成的文章与现在一致，不增加请求。
- 被截断的文章会自动补完一次，无需手动点击。
- 极端情况下仍未完成，页面会明确提示并允许手动续写。

## 测试

- 验证生成和续写请求均使用 12000 的输出上限。
- 验证完整响应不会触发自动续写。
- 验证 `max_tokens` 停止原因和半句结尾会触发一次自动续写。
- 验证自动续写最多一次，避免无限请求。
- 验证跨网络数据块的 SSE 消息不会丢失正文。
- 运行现有全部测试，确认模型选择、API 地址和数据保存功能不回归。
